# GymLog 界面改版設計需求（交給 Claude Design）

> 附件：`screenshots/`（14 張 iPhone 17 Pro 模擬器截圖，1206×2622 px，對應 402×874 pt）與 `reference-code/`（現行 SwiftUI 實作與設計 token）。截圖中的學員和訓練數據均為合成示例。

## 你的任務

GymLog 是一款給私人教練使用的 iOS 訓練記錄 App（SwiftUI，iOS 26，繁體中文為預設介面語言，另支援英文）。教練在健身房現場邊帶學員邊記錄：組數、重量、次數、組間休息、CrossFit WOD、心率，並在事後查看歷史課次與 InBody 體測數據。

請為下列 **6 組畫面** 產出高保真 iPhone 設計稿（402×874 pt），每組包含必要的狀態變體，並給出動效規格。設計必須延續現有視覺語言（暖米色底 + 深墨綠文字 + 赤陶橘強調色、大圓角白卡片、底部浮動 Tab Bar），是「同一個 App 的升級」，而不是換一套品牌。

使用情境決定了設計取捨：教練單手持手機、站著、常在兩組之間的幾十秒內操作，並用餘光掃一眼狀態。因此優先級是 **一眼可讀 > 大命中區域（≥44pt）> 資訊密度 > 裝飾性**。

## 1. 今天 · 左上角「組間休息倒計時」

**截圖**：`01_today_empty_session.png`（閒置，顯示 1:00）、`02_rest_timer_running.png`（運行中，0:58）

**現狀**：左上角一顆膠囊（計時圖示 + `1:00`），點擊開始／暫停／繼續，長按彈出 30/45/60/90 秒預設與重置。運行時膠囊底色從左到右做線性填充表示進度，結束時整顆變橘色並響鈴。問題是填充進度幾乎看不出來，缺乏「時間正在流逝」的感受。

**需求**：
- 點擊開始後，倒計時以 **圓環（ring）逐漸減少** 的動畫呈現，圓環中央是剩餘秒數。
- 請設計以下狀態：閒置（預設時長）、運行中、暫停、最後 5–10 秒（提醒即將結束）、結束（響鈴狀態），以及長按時的時長預設選單。
- 請判斷並提出圓環的呈現位置：(a) 左上角膠囊本身變形為一個小圓環；或 (b) 點擊後展開成較大的浮層／卡片圓環，可收回為角落小圓環。可以兩者兼有（展開 + 收合）。說明你的選擇理由——注意畫面下方仍要能繼續記錄組數。
- 動效：圓環應連續平滑遞減（非每秒跳格），給出緩動曲線、結束時的強調動效、以及系統「減少動態效果」開啟時的替代方案。
- 數字使用等寬數字（monospaced digits），避免跳動。

## 2. 今天 · 右上角「開始運動 → 心率記錄」

**截圖**：`01_today_empty_session.png`（膠囊顯示灰色心形 +「開始運動」）、`03_heart_rate_sheet.png`（點擊後彈出的心率面板）

**現狀**：右上角膠囊文字「開始運動」，看不出它與心率有關；點擊後彈出一個列表式面板（即時心率、選擇藍牙裝置、Garmin 手環設定說明文字），連上後膠囊顯示 BPM 數字，心形僅輕微放大。模擬器沒有藍牙，所以截圖只能呈現「此裝置不支援藍牙 / 正在搜尋」狀態。

**需求**：
- 入口文案與圖示要明確提示「記錄心率」（例如「記錄心率」或「開始運動 · 心率」，請給建議），讓教練知道點下去是連接心率帶／手環。
- 連接成功後：**跳動的心臟動畫 + 大號即時心率數字（BPM）**。心跳節奏應與實際 BPM 同步（例如 120 BPM = 每 0.5 秒一次搏動），請給出縮放幅度、時長與緩動。
- 請設計以下狀態：未開始、搜尋中、連接中、已連接（即時 BPM 跳動）、訊號中斷／暫無數據（`--`）、藍牙不可用。
- 重新設計彈出的心率面板：即時 BPM 作為視覺主角；本次課的「平均 / 最低 / 最高」匯總；裝置列表（裝置名 + 訊號強度 dBm）；手環設定說明應摺疊或弱化，不要一整段灰字。可選加入簡單的心率區間色帶或本次課心率走勢小圖（標註為可選，現有數據有逐秒 BPM）。

## 3. 選擇動作（Exercise Picker）與單項動作卡片

**截圖**：`04_exercise_picker.png`（選擇動作面板）、`05_single_exercise_card.png`（加入後的單項動作卡片）、`09_exercise_query.png`（歷史頁的「單項查詢」，若一併優化請保持風格一致）

**現狀**：
- 選擇動作面板：頂部分類膠囊（全部 / 常用 / 力量 / CrossFit / 推 / 拉 …，可橫向滑動）+ 右側橘色 `+` 新建；中間是 244 個動作的純文字長列表（「中文名（English）」+ 灰色「動作模式 · 器械 · CrossFit」）；底部浮動搜尋框。問題：列表單調、無視覺錨點，長英文名換行擁擠，難以快速掃讀。
- 單項動作卡片：動作名、摘要（Round 數 · 組數 · 休息 · 估算 kcal）、趨勢與刪除圖示、每個 Round 一行四個膠囊（組數 / 重量 / 目標 / 實際），「添加 Round」。

**需求**：
- 提升掃讀效率：考慮以動作模式（蹲 / 推 / 拉 / 髖鉸鏈 / 核心 / 體能）做圖示或色標、器械標籤化、「常用 / 最近使用」置頂、字母或分類索引、名稱中英文主次層級更清楚。
- 卡片需保留現有數據欄位，但讓「重量」與「實際完成」這兩個現場最常改的數值更突出，並清晰區分「目標」與「實際」。
- 注意：所有數值目前透過點擊後彈出滾輪（wheel picker）修改，請保留「點擊即改」的交互。

## 4. WOD 卡片（重點優化）

**截圖**：`06_wod_card_top.png`（WOD 卡片上半：類型 AMRAP、名稱、時限步進器、動作列表）、`07_wod_card_bottom.png`（下半：加動作、加一輪、現場計時、成績分段控件）、`08_wod_live_timer.png`（現場計時運行中，11:33）

**現狀**：WOD 卡片是一張非常長的表單：`WOD` 小標、`AMRAP` 類型切換（文字按鈕）、名稱（選填）、估算 kcal、時限 `12:00` + 灰色 −/+ 步進器、動作行（動作名下拉 + 數量 + 單位下拉 + 負重/標準下拉 + 刪除）、「加一個動作」、「加一輪（不同數量，如 21-15-9）」、現場計時（開始計時 → 大號時間 + 暫停 / 結束）、成績（未記錄 / 完成 / 超時 / 中止）。問題：層級扁平、控件風格不一致（橘色文字、灰色步進器、iOS 原生分段控件混用）、計時器與處方混在一起，卡片過長導致現場需要大量滑動。

**需求**：
- 重新組織資訊架構：清楚分為「處方（Prescription）」「現場計時（Live）」「成績（Result）」三段，並考慮計時運行時把計時器提升為視覺主角（例如計時中處方收合、只保留動作清單速覽）。
- WOD 類型目前支援 AMRAP / For Time / EMOM / Interval（工作/休息間歇，如 Tabata 20s/10s×8，定義見 `reference-code/WODPrescription.swift`），要有明顯、可切換的呈現，並依類型改變計時器語義（AMRAP 倒數、For Time 正數 + 時限、EMOM 每分鐘循環、Interval 工作/休息交替）。成績另有 Rx / Scaled 標記。
- 現場計時請與第 1 項的圓環倒計時保持同一套視覺語言（例如 AMRAP 用倒數圓環，For Time 用正數 + 時限上限）。
- 成績記錄：AMRAP 需要「輪數 + 額外次數」，For Time 需要「完成時間」；請設計對應輸入方式，而不只是四選一分段控件。
- 統一控件：步進器、下拉、分段控件使用同一套樣式與圓角。

## 5. 個人信息 · 底部 InBody 體測數據（大幅美化）

**截圖**：`11_profile_inbody_list.png`（學員檔案頁底部 InBody 區塊：日期 + 小字網格數值，下方「新增一條 InBody 記錄」「掃描報告照片」）、`12_inbody_detail.png`（單條記錄詳情：表單式列表）

**現狀**：InBody 記錄以純文字小網格列出（體重 / 體脂率 / 體脂重 / 骨骼肌 / BMI / 內臟脂肪），只有部分欄位填寫的記錄會參差不齊；詳情頁是設置頁式的鍵值列表。沒有任何趨勢、對比或視覺化。

**可用數據欄位**（每條記錄）：日期、體重 kg、體脂率 %、體脂重 kg、骨骼肌量 kg、BMI、內臟脂肪等級、BMR、TDEE、備註。任何欄位都可能為空。

**需求**：
- 設計一個「身體組成」總覽模組：最新一次的關鍵指標大數字（體重、體脂率、骨骼肌量）+ 與上一次相比的變化量（↑↓ 與顏色，注意體脂下降是正向、肌肉上升是正向）。
- 趨勢圖：體重 / 體脂率 / 骨骼肌量隨時間變化（可切換指標），需處理只有 1–2 個數據點與欄位缺失的情況。
- 歷史記錄列表：卡片化、欄位缺失時的優雅降級（不要留空洞）。
- 詳情頁：從鍵值列表改為視覺化呈現，例如 BMI / 內臟脂肪等級的區間條（標準範圍標示）、體脂與肌肉的構成比例圖。
- 「新增記錄」與「掃描報告照片」兩個入口保留，並給予更清楚的主次層級。

## 6. 歷史 · 課次列表與課次詳情

**截圖**：`20_history_list.png`（多日課次列表）、`30_session_detail_1.png`（詳情上半：運動消耗卡、AI 訓練評價卡、熱身）、`31_session_detail_2.png`（詳情下半：單組與超級組的逐組數據）

**現狀**：
- 列表：一張長白卡內每行「日期（大字）· 第 N 週 · 學員 · N 個訓練塊 · 完成後估算：資料不足（部分）」，每一行長得一模一樣，無法區分當天練了什麼、強度如何；「資料不足」這類狀態文字佔據主要位置。
- 詳情：上方兩張說明性質的卡片（運動消耗需要體重、AI 評價需要雲端服務）在數據不全時佔據首屏；逐組數據每行都帶「推斷」標籤，視覺噪音大。

**列表可用數據**：日期、週次、學員名、訓練塊數量與各塊動作名、WOD 摘要（類型/時限/成績）、估算消耗 kcal（可能部分或缺失）、AI 評價摘要（可能無）、「進行中 / 日期已還原 / 待復核」狀態標籤、每組重量與次數（可計算總訓練量 kg、主項最大重量、PR）。

**需求**：
- 列表：依週或月分組（sticky header），每張課次卡片呈現「練了什麼」（主要動作名或動作模式圖示）與「練得多重」（總訓練量、最大重量或 kcal），PR 與進行中狀態要醒目；可選在頂部加入月曆熱力圖或本週／本月訓練頻率概覽。
- 詳情：首屏應先回答「這堂課練了什麼、表現如何」——建議頂部是課次摘要（日期、時長、總量、kcal、心率平均若有），數據不足的說明卡改為可收合或次要提示。
- 逐組數據：弱化「推斷」這類元數據標籤（例如整塊只標一次，或使用小圓點），讓重量 × 次數成為主角；超級組 A/B 的從屬關係保持清晰；PR 組高亮。

## 設計約束

1. **視覺 token（必須沿用，可擴充不可替換）** — 詳見 `reference-code/DesignSystem.swift`。

   | Token | 淺色 | 深色 | 用途 |
   |---|---|---|---|
   | canvas | #F6F2EA | #0E1013 | 頁面底色 |
   | surface | #FFFFFF | #181C21 | 卡片 |
   | inset | #F1EDE3 | #22272D | 輸入膠囊、內嵌區 |
   | hairline | #E7E0D3 | #2C333A | 分隔線 |
   | textHi / textMid / textLow | #1A2B25 / #5F645F / #8A8578 | #F4F6F3 / #A3ADB5 / #6C7780 | 文字三級 |
   | accent / accentSoft | #C05A2E / 12% | #C7ED3E / 13% | 強調色（深色模式為螢光黃綠） |
   | danger | #A63A28 | #E2624B | 刪除、錯誤 |
   | pr / prBg | #B8870B / #FAEFD0 | #F2C74D / 14% | PR 標籤 |
   | inferred / review / restored | #9A5B2A / #2E5A4C / #7A6A45 | #E8B65E / #8FC0F0 / #C7A3E8 | 數據來源標籤 |

   字體為 SF（系統字體），頁面標題 30 Heavy、卡片標題 17 Bold、數據數字 19 SemiBold、數字一律等寬。圓角：卡片 16、控件 14、步進器 12、標籤 6、膠囊全圓。頁邊距 16、卡片間距 10、卡片內距 14。

2. **淺色與深色模式都要出稿**（深色模式強調色為 #C7ED3E，心率紅色與圓環顏色需在兩種模式下都檢查對比度）。
3. **可實作性**：目標是 SwiftUI 原生實作。避免依賴自訂字體檔、複雜 3D 或需要 Lottie 的動畫；圓環用 `Circle().trim` 級別可實現的效果即可。
4. **保留全局元素**：頂部學員切換器（`● Alex ⌃⌄` + `+`）、左下角橘色麥克風語音按鈕、底部五個 Tab（今天 / 個人信息 / 歷史 / 動作庫 / 設置）位置不變，新設計不得被它們遮擋。
5. **文案**：繁體中文，簡潔；新增或修改的文案請在設計稿旁標出，並提供英文對照。
6. **無障礙**：命中區域 ≥44pt；動態效果需有「減少動態效果」替代；色彩不是唯一的狀態訊號（配合圖示或文字）。
